# Authoring status and release gates

## Scope

This first increment establishes the LiveLabs folder structure, six learner labs, prompt templates, a direct OCI API runner, local validation, and a deploy-request renderer. It preserves the agreed five-stage learning journey and adds explicit cleanup.

The running app is generated by attendees. There is no checked-in completed app, approved comprehensive ADR, validated bootstrap stack, or tested fallback image in this increment.

## Instructional design

Each lab has a purpose, objectives, prerequisites, numbered tasks, expected results, observe-the-behavior prompts, troubleshooting, and a completion checkpoint. The generation lab includes a controlled prompt refinement and comparison. Live tests include persistent memory, rejected actions, ownership isolation, and cleanup.

Use the same terms throughout: **Operations Command Center**, **Active Resources**, **Review Action**, and **Confirm**. These UI contracts are supplied to the model in the brief.

## Release gates

| Gate | Evidence required | Current state |
| --- | --- | --- |
| Content and starter checks | Manifest/link checks and runner tests | Run during authoring; results in validation report |
| Comprehensive ADR | Approved architecture, tool/API contracts, data model, authentication, confirmations, and retry semantics | Pending design |
| Generation benchmark | Repeated complete generations from a fixed model/configuration; repair counts, token usage, elapsed time | Pending live pilot |
| App acceptance suite | Independent API/UI tests for creation, scope, confirmation, retries, and audit | Pending implementation after ADR |
| Bootstrap infrastructure | Repeatable IAM/network/ADB/Vault/OCIR setup and per-attendee outputs | Pending implementation |
| Runtime identity | Model, embeddings, Vault, SQL, and OCI tools tested under the Container Instance principal | Pending live pilot |
| OCI deployment | Native architecture build, private OCIR push/pull, quota/capacity, readiness, HTTPS access | Pending live pilot |
| Resource lifecycle | Create/observe/delete owned Compute resource; verify boot-volume behavior | Pending live pilot |
| Recovery | Tested known-good source/image checkpoint and bounded repair path | Pending benchmark |
| Event calibration | Human pilot timing, P50/P90, facilitator interventions | Pending pilot |

Static checks are authoring evidence. A generated file compiling is not application acceptance. Do not remove the draft notices or register the workshop as ready until the required gates have evidence.

## Next implementation sequence

1. Finalize the comprehensive app ADR and replace the working brief with approved requirements.
2. Create the bootstrap stack and independently authored app acceptance tests.
3. Run one complete generation/deployment/lifecycle pilot in a designated test compartment.
4. Fix prompts and guides against captured evidence; publish a tested recovery artifact.
5. Run repeated generations, then a human pilot and event calibration.
